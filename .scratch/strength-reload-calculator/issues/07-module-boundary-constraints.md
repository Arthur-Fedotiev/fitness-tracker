## Question

Surfaced while discussing [UI flow prototype](04-ui-flow-prototype.md)'s exercise-picker reuse: `.eslintrc.json`'s `@nx/enforce-module-boundaries` `depConstraints` only had a rule for `domain:exercise`, and it referenced a `domain:workout/api-public` tag that doesn't exist anywhere in the repo. `domain:workout` had no constraint at all — nothing lint-enforced that `workout` could only reach `exercise` through `exercise/public-api`. Before scaffolding `libs/program/*`, close this gap and add a matching constraint for the new `domain:program` tag so the boundary is enforced from day one, not just by convention.

## Answer

Fixed directly (small, mechanical, low-risk — done in-session rather than left as a future ticket):

- `.eslintrc.json`: deduped the accidental duplicate `domain:shared` entry; corrected `domain:exercise`'s rule to `["domain:exercise", "domain:shared"]` (dropped the reference to the nonexistent `domain:workout/api-public` tag — `exercise` never depends on `workout` in either direction); added `domain:workout: ["domain:workout", "domain:shared", "domain:exercise/api-public"]`; added `domain:program: ["domain:program", "domain:shared", "domain:exercise/api-public"]` ahead of the domain's libs existing, mirroring `domain:workout`'s shape.
- Turning on the `domain:workout` constraint would have immediately broken the build: three files imported `ExerciseFacade` / `EXERCISE_DESCRIPTORS_PROVIDER` straight from `@fitness-tracker/exercise/domain` (tagged `domain:exercise`, not `domain:exercise/api-public`) instead of through `exercise/public-api`.
- **Revised approach, per user correction:** rather than re-exporting the whole `ExerciseFacade` class through `exercise/public-api` (which would violate Interface Segregation — consumers would depend on every capability the facade has, not just the one they use), the actual capability the three files needed — `openExerciseDetailsDialog(id)` — was extracted into its own narrow interface + `InjectionToken`: `OpenExerciseDetailsDialogCommand` / `OPEN_EXERCISE_DETAILS_DIALOG_COMMAND`, in `libs/exercise/domain/src/lib/entities/commands/open-exercise-details-dialog.command.ts`, matching the codebase's own pre-existing `ExerciseDetailsQuery`/`LoadExerciseDetailsCommand` pattern. `ExerciseFacade` now also implements it, wired via `useExisting: ExerciseFacade` in `EXERCISE_DOMAIN_PROVIDERS`, and only the narrow interface + token are exported from `exercise/public-api` — not the facade itself. The three files inject the narrow token, not `ExerciseFacade`.
- This convention — narrow public-api interfaces via injectable tokens, alongside the lint-enforced `domain:*` boundary — is now documented in root `CONTEXT.md` under "Architecture conventions", so it isn't rediscovered ad hoc next time a domain needs to expose something.
- When [UI flow prototype](04-ui-flow-prototype.md)'s exercise picker is actually built, it should follow the same convention: mint its own narrow query/command interface(s) for whatever slice of `ExerciseFacade`'s querying/filtering it actually uses (e.g. a `FindExercisesQuery`), rather than exporting `ExerciseFacade` or `FindExercisesSearchOptions` wholesale through `exercise/public-api`. Nothing like that is exported today — deliberately, since no consumer needs it yet.
- Verified via `nx lint` across every `domain:exercise`- and `domain:workout`-tagged project: zero new `@nx/enforce-module-boundaries` violations. The one boundary-adjacent lint error that appeared (`exercise-feature-display`'s lazy-load static-import warning) was confirmed pre-existing on `main` via `git stash` — part of the known lint baseline, untouched by this change.

Decided and executed in conversation with the user, 2026-08-12 — an explicit override of wayfinder's default "plan, don't do," since the user asked to close the gap directly rather than leave it as a future ticket. The user also corrected the first pass mid-session to enforce Interface Segregation at the public-api seam rather than re-exporting the whole facade.
