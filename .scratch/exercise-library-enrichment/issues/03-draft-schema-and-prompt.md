## Question

Using the finalized taxonomy from [Finalize the exercise taxonomy](02-finalize-taxonomy.md) and the existing exercise inventories from [Pull existing exercise names (prod + staging)](01-existing-exercise-names.md) (both admin-owned document IDs — needed since regeneration overwrites in place — and names), draft:

1. The per-exercise JSON schema: `name`, `exerciseType`, `targetMuscles: string[]`, `equipment`, `instructions` (matching the live `Exercise` shape from [ADR-0005](../../../docs/adr/0005-flatten-exercise-basedata.md), plus the new `targetMuscles` array). Include the document `id` for regenerated (existing) entries so the eventual overwrite is unambiguous.
2. The actual ChatGPT prompt text. This now targets a **full regeneration** of the admin-owned library (per the map's reseed-in-place redraw), not gap-filling: it should cover every currently-admin-owned exercise (regenerate its content) plus fill in missing popular main lifts, powerlifts, olympic lifts, and functional/conditioning movements; constrain output to the finalized taxonomy values; specify strict JSON output.

Use `/prototype` to produce a concrete draft (schema + prompt + a sample generated batch) for the human to react to and iterate on. This ticket's answer is the finished prompt + schema, ready to run — running it, reviewing the output, and executing the overwrite/delete is the human's next step, outside this map (see the map's Out of scope section).

## Answer

Drafted via `/prototype`, with a deviation from that skill's default LOGIC/UI HTML-artifact templates noted below. Three ready-to-run files, saved as assets (not pasted inline, per convention):

- [exercise-regeneration.schema.json](../assets/exercise-regeneration.schema.json) — OpenAI structured-outputs-compatible JSON Schema (`strict: true`). Root is `{ "exercises": [...] }`; each entry has `id` (string or `null` — `null` means genuinely new, no existing document), `name`, `exerciseType` (8-value enum), `targetMuscles` (array, 19-value enum, `minItems: 1`), `equipment` (20-value enum), `instructions` (array, `minItems: 3`). Enum values are copied verbatim from the finalized taxonomy in [Finalize the exercise taxonomy](02-finalize-taxonomy.md) / `exercise-descriptors.provider.ts`. `equipment` stays singular (matches the live `Exercise` shape from ADR-0005); only `targetMuscle` widens to the new `targetMuscles: string[]`, per the map's decision.
- [exercise-regeneration.prompt.md](../assets/exercise-regeneration.prompt.md) — the actual prompt text, ready to paste into ChatGPT or pass as an API `input`. Covers: task framing (regenerate all 158 admin-owned docs in place + add missing popular main lifts/powerlifts/oly lifts/functional movements), output rules (id-copying, name-preservation, cross-environment duplicate handling, avoiding re-adding exercises that already exist under another name), the full taxonomy with line-drawing guidance for the ambiguous `exerciseType` calls (carried over from ticket 02's answer), an explicit callout of the 14 corrupted-`targetMuscle` documents (flagged inline with `⚠`) so the model doesn't defer to the bad data, the full 158-row existing-exercise list (id + name, both environments, pulled from [Pull existing exercise names (prod + staging)](01-existing-exercise-names.md)'s inventory assets), a starter list of candidate new exercises, and a "how to run this" section covering both the API (single call, schema-enforced) and the ChatGPT web-UI (batched by chunk, since there's no schema enforcement there and quality degrades over very long outputs).
- [exercise-regeneration.sample-batch.json](../assets/exercise-regeneration.sample-batch.json) — a hand-crafted 10-entry sample of what a real run should produce: a straightforward regeneration (Dumbbell Bench Press), three of the corrupted-`targetMuscle` fixes (Barbell Glute Bridge, Dumbbell Lying Pronation, Dumbbell Farmer's Walk), a name-cleanup case (leading-whitespace trim), the cross-environment duplicate-id-same-content case (Clean and Jerk, two ids), a `FUNCTIONAL`/`SLED` regeneration (Sled Push), and three brand-new `id: null` entries (Wall Ball Shot, Overhead Press, Turkish Get-Up) spanning `FUNCTIONAL`/`STRENGTH`. Validated programmatically against the schema's enums and structure — zero violations.

**Deviation from `/prototype`'s default templates**: the skill's two branches (LOGIC.md's single-HTML-file state-machine demo, UI.md's routed UI variations) both assume a runnable code artifact meant to be folded into the real codebase once validated. This ticket's deliverable is a text/data artifact (a schema + prompt string + sample JSON) meant to be run against an external tool (ChatGPT) — there's no state machine, no UI, and no "real code" to fold a validated decision into. Followed the skill's shared rules in spirit (throwaway, clearly marked as a draft, concrete enough to react to) but skipped the HTML-template mechanics and the "capture on a throwaway git branch" step — these are markdown/JSON planning assets, saved as ticket assets per the wayfinder/local-markdown-tracker convention (matching how ticket 01's inventory JSON was captured), not application code.
