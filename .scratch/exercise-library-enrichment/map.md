# Exercise library enrichment

## Destination

A finalized exercise taxonomy (muscles, equipment, exerciseTypes), a JSON schema, and the actual regenerated content for the entire admin-owned exercise library — generated directly by us, not handed off to ChatGPT — covering popular main lifts, powerlifts, olympic lifts, and functional/conditioning movements (sled push/pull, wall balls, etc). Every currently-admin-owned document gets fresh content (same document ID, in-place overwrite — no workout reference ever dangles); genuinely new exercises get new documents. The output is reviewed by hand before persisting; the actual persist/overwrite-to-Firestore execution is out of scope for this map (see Out of scope).

## Decisions so far

- [Reseed-in-place redraw](map.md) — switched from additive-only to full in-place regeneration of every admin-owned exercise (same doc ID, new content), after a read-only survey confirmed near-zero blast radius (see Notes). The one orphaned user-owned exercise gets deleted. Persisting/overwriting execution itself stays out of scope for this map.
- [Finalize the exercise taxonomy](issues/02-finalize-taxonomy.md) — 8 exerciseTypes (added `FUNCTIONAL`, renamed `WEIGHTLIFTING`→`OLYMPIC_WEIGHTLIFTING`), 19 muscles (added `OBLIQUES`/`HIP_FLEXORS`/`ADDUCTORS`/`ABDUCTORS`, fixed the `LOWE_BACK` typo), 20 equipment values (added `SLED`/`TRAP_BAR`/`ROWER`/`JUMP_ROPE`/`BATTLE_ROPES`/`BOX`/`SANDBAG`). Applied to code: `exercise-descriptors.provider.ts` updated, dead value-enums deleted from `exercise.enums.ts`. Also surfaced that 14 of 158 live admin exercises have corrupted `targetMuscle` data (equipment names or literal `"NULL"`).
- [Draft the JSON schema and ChatGPT prompt](issues/03-draft-schema-and-prompt.md) — finished, ready-to-run schema + prompt + validated sample batch, saved as assets: [schema](assets/exercise-regeneration.schema.json), [prompt](assets/exercise-regeneration.prompt.md), [sample batch](assets/exercise-regeneration.sample-batch.json). Prompt covers all 158 existing docs (id-preserving regeneration, corrupted-data callout, cross-env duplicate handling) plus new popular lifts. Surfaced a third stale taxonomy duplicate in `ExerciseResponseModel`'s static arrays (ticket 02 missed it) — spun out as its own ticket rather than folded in here.

- [Generate the regenerated exercise content ourselves](issues/05-generate-regenerated-content-ourselves.md) — produced the full batch directly (no ChatGPT call): 143 unique existing document ids (covering all 158 staging+prod rows, 15 of which share a literal id across both environments) regenerated in place, plus 19 new exercises, saved as [exercise-regeneration.output.json](assets/exercise-regeneration.output.json). Programmatically validated against the schema (enums, minItems, required fields, id-uniqueness) — 0 errors. Amended after review caught naming/identity issues (see next two entries).
- [Verify ambiguous exercise identities before trusting the generated batch](issues/06-verify-ambiguous-exercise-identities.md) — traced the library to the public `free-exercise-db` dataset; corrected 8 of 9 flagged entries in the output asset (Moving Claw Series→Sprint Claw Drill, Power Partials→Dumbbell Lateral Raise (Partial Reps), Vertical Swing→Dumbbell Swing, Upper Back-Leg Grab→Seated Hamstring and Upper Back Stretch, Downward Facing Balance→Stability Ball Plank Hold, Suspended Hip Thrust→TRX Hip Thrust, The Straddle→Seated Straddle Stretch, Kneeling Squat→Barbell Kneeling Squat, the last of which fixed an accidental copy-paste from the separate Kneeling Jump Squat entry). "Backlash with Dumbbells" (id `UNpo9QQILw9SQOsWteZW`) stayed unidentifiable — left as an unverified guess, flagged for a human decision (see Notes).

## Out of scope

- Executing the regeneration — overwriting admin-owned docs in place, creating new docs, and deleting the one orphaned user-owned exercise — deferred to a future effort once the reviewed JSON exists. This is real destructive/production-writing work and deserves its own careful, human-driven session.

- Reviving or populating the orphaned `muscles`/`exercise-types`/`equipment` Firestore collections — this effort's taxonomy lives in code (`exercise-descriptors.provider.ts`), not those collections, which predate the current architecture and have zero consumers.
