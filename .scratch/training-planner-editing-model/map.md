# Training Planner Program Save & Edit Model

Label: wayfinder:map

## Destination

A shipped, coherent editing/persistence model for the Training Planner (`program` domain) dashboard, replacing today's immediate-persist-per-action pattern with an explicit Program-level edit session: Draft Programs are always editable; Active/Completed Programs are read-only with an Edit button. Inside an edit session, Program name and Main Lift Block additions/removals/inputs stage locally and commit in one Program Save. Generate becomes a pure, non-persisting preview computed from live (possibly-unsaved) form data. The map closes once every ticket below resolves, delivering: (1) a real Program name field with a computed default and rename UX, (2) an exercise-picker flow that stages a block card immediately on selection, (3) the unified edit-session/save architecture, and (4) read-only-with-Edit-button treatment for Active/Completed Programs.

## Notes

- Ground truth for current implementation lives in `libs/program/{domain,ui,feature-dashboard,shell}` — read `program.store.ts`, `program-dashboard.component.ts`, and `main-lift-block-form.component.ts` before any ticket. Every store method today does an immediate whole-document `setDoc` via `ProgramService.updateProgram`; that's exactly the pattern this map replaces.
- Prior architecture (signalStore, Firestore schema, module boundaries) is settled in the closed [Strength Reload Calculator map](../strength-reload-calculator/map.md) and [ADR-0007](../../docs/adr/0007-introduce-program-domain-for-strength-reload.md) — don't re-litigate those; this map only revises the editing/persistence UX on top of them.
- Settled during destination-naming, not worth their own tickets: Week 8 Retest stays an immediate, always-available action outside the edit session (unchanged from today); default Program name's date range is `createdAt` → `createdAt + 8 weeks` (the standard Reload Cycle length), formatted "Strength Cycle \<Mon\> - \<Mon\> \<Year\>".
- Default every ticket to `/grilling` + `/domain-modeling` unless its `Type:` line says otherwise; tickets marked `prototype` should also run `/prototype` per its own skill.
- [Edit-session architecture](issues/02-edit-session-architecture.md) is the crux — it blocks the picker, generate-preview, and read-only-UI tickets. Resolve it first.

## Decisions so far

- [Drop block-level Apply button](issues/07-drop-block-level-apply-button.md) — Apply is gone; a block's Test/Loading Constraint stage into the draft automatically on blur (only if valid), Program Save is the sole persist action and disables whenever any visible block is invalid, no new "staged" affordance beyond existing field errors. Surfaced after map close, when the user questioned ticket 05's Apply-button rationale; overturns that ticket's "keep it as an explicit click" call.
- [Unsaved-changes navigation guard](issues/06-unsaved-changes-navigation-guard.md) — three leave-surfaces guarded: `CanDeactivate` on the `training-planner` route (nav away), a bare `beforeunload` listener (tab close/refresh, native prompt only), and in-component interception of Program/status-tab switches (not a route transition). Route-away and in-page switches share a three-option `DiscardChangesDialogComponent` (Save & leave / Discard & leave / Stay), Save & leave awaiting `store.saveProgram()`. "Dirty" is a structural diff of `draftProgram` against last-persisted, not a sticky touched-flag, applied uniformly to Draft and Active/Completed sessions.
- [Read-only/Edit-mode UI](issues/05-readonly-edit-mode-ui.md) — Active/Completed Programs disable form inputs and hide Generate/Add/Remove outside a single per-Program Edit session (full scope even for Completed); Save/Cancel replace the Edit button in place; Cancel confirms via a dialog only when dirty, shared with the navigate-away guard; block-level button relabeled "Apply". Prototyped 3 variants on the real dashboard (`?variant=A|B|C`); Variant B ("Whole-grid edit frame") won and is folded into `ProgramEditToggleComponent`/`DiscardChangesDialogComponent`; the rest live on throwaway branch `prototype/05-readonly-edit-mode-ui`. Along the way, fixed a pre-existing Generate/Apply-ordering bug and several card/table CSS layout issues unrelated to this ticket's own scope.
- [Generate preview behavior](issues/04-generate-preview-behavior.md) — Generate stays an explicit click-triggered snapshot (no reactive recompute); a shown table (fresh or prior-Save) goes visibly stale (text + color, not color alone) the instant an input changes, until the next Generate. Manual Week 5 becomes a new persisted field on `MainLiftBlock` (overturns the ticket's original premise that it stays unpersisted) — staged/committed like `anchorSource`/`cycle`, rehydrated into the form on reopen when `anchorSource === 'manual'`, and nulled whenever a regenerate drops the override.
- [Block-picker auto-stage flow](issues/03-block-picker-auto-stage-flow.md) — `AddMainLiftBlockComponent` becomes a toggle trigger button; picking an exercise commits immediately and closes the picker (Variant B, prototyped against two rejected variants on branch `prototype/03-block-picker-auto-stage-flow`). No differentiated Remove affordance for staged vs. persisted blocks — moot, since edit-session architecture already stages all removal. Folded directly into real code.
- [Edit-session architecture](issues/02-edit-session-architecture.md) — single-slot `draftProgram` on `ProgramStore`; name/blocks/test-inputs/generated-cycle/retest/manual-completion all stage locally and commit in one `saveProgram()`; Cancel re-seeds from last-persisted; Draft→Active and Active→Completed each get a computed Save-time status rule. Overturns the map's original "retest stays immediate" note — retest is now staged too, for one consistent commit model.
- [Program name default & rename UX](issues/01-program-name-default-and-rename-ux.md) — new section header above the block grid; pencil toggles an inline `matInput`; default name `Strength Cycle <Mon> - <Mon> <Year>` computed client-side at creation (no more `'New Program'` flash); 60-char max, required non-empty. Prototyped 3 variants, chose the minimal-inline one, folded into real code (`ProgramNameHeaderComponent`, `computeDefaultProgramName`); renames stage in-memory pending Edit-session architecture's real `draftProgram`/`saveProgram()` wiring.

**Destination reached.** All six original tickets resolved (see Decisions so far). Ticket 02 (edit-session architecture: `draftProgram`/`saveProgram()` on `ProgramStore`) is still unimplemented in code as of map close — the dashboard runs on the pre-decision prototype stand-in (`editingProgramId`/`dirty`/`nameOverrides` in `program-dashboard.component.ts`); this map's decisions are the spec for that build-out, not the build itself.

**Reopened once, now closed again.** Reviewing that prototype stand-in against the real dashboard surfaced [Drop block-level Apply button](issues/07-drop-block-level-apply-button.md), which questioned ticket 05's rationale for keeping an explicit per-block commit click. Resolved — no further tickets remain. (A second question raised in the same review, about the Week 8 Retest input staying editable outside an Edit session, turned out on inspection to be a wiring bug against the already-decided behavior, not a new decision — tracked as a fix, not a map ticket.)

**Real build landed (2026-08-14).** Ticket 02's architecture is now implemented, along with everything it blocked: `ProgramStore` gained a single-slot `draftProgram`/`dirty`/`sessionEpoch` plus `beginEditSession`/`cancelEditSession`/`stageRename`/`stageAddMainLiftBlock`/`stageRemoveMainLiftBlock`/`stageMainLiftBlockInputs`/`stageGeneratedCycle`/`stageWeek8Retest`/`saveProgram()`, replacing every old immediate-write method except `createProgram`/`deleteProgram` (which stay immediate per the ticket). Both prior gaps are fixed: `stageRename` gives rename a real persistence path, and the chip lists now correctly show only last-persisted names (staged renames not yet reflected anywhere but the open session's own header — that's the real architecture working as designed, not a bug to patch). The block-level Apply button is gone (`(focusout)` auto-stage in `MainLiftBlockFormComponent`, gated on validity); Program Save is the sole persist action and disables whenever any visible block is invalid (`saveDisabled` in `program-dashboard.component.ts`, fed by a `validityChange` output threaded up from the form). `MainLiftBlock` gained `manualWeek5: number | null`, staged/rehydrated/cleared per ticket 04. Generate-preview staleness is tracked in `MainLiftBlockCardComponent` (a `stale` signal, reset on a `sessionEpoch` input bumped only at session begin/cancel/save — not on ordinary field staging) and surfaced in `ReloadCycleTableComponent` via text + dimmed color. The three-option unsaved-changes dialog (`DiscardChangesDialogComponent`, extended with an optional `saveLabel`) backs a `CanDeactivate` guard (`trainingPlannerDeactivateGuard` in `program/shell`) and a `beforeunload` listener, both reading `store.dirty()`; in-page Program/status-tab switches and Program creation route through the same guard. Draft Programs now render the same `ProgramEditToggleComponent` as Active/Completed (always showing Save/Cancel, never Edit, since `readOnly()` is always false for Drafts) rather than being hidden as before. Verified via a full `nx build fitness-tracker` (catches template type errors) plus lint/unit tests on all four `program/*` libs, and manually exercised in a browser by the user against the `fitness-tracker-ui-dev` Firebase project.

**Follow-up polish landed the same day**: action-button spacing/grouping, Program-name truncation and mobile grid overflow fixes, icon+tooltip Save/Cancel, full-width exercise picker, "Min available increment" label, per-user Program-name uniqueness (blocked on rename with inline error, auto-suffixed on create), and Generate/Save validity now conditional on Manual override (1RM + Reps @ 80%1RM required outside Manual, optional inside it, with a short in-form hint) — `RepMaxTest.oneRepMax` is now nullable to support that. Also fixed a `MatTabGroup` visual-desync bug where a blocked status-tab switch left the tab header stuck on the clicked tab.
