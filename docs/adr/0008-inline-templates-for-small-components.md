# Inline component templates for small-to-average components

Angular components in this repo have always used the 3-file split (`.ts` / `.html` / `.scss`) generated by `@nx/angular:component`. We're changing that for templates only: a component whose template is 100 lines or fewer gets it written inline as a bare template-literal string on the `template` property, in the `.ts` file, not a sibling `.html`. Past 100 lines, split it back out into `.html`. Stylesheets stay in a sibling `.scss` file regardless of size, for now — inlining styles too was considered and deferred rather than ruled out; revisit once there's a concrete reason to.

Picked 100 lines (measured on the template alone, independent of the component's TypeScript body — a component's logic size and its markup size are orthogonal) because it comfortably covers every component in `program/ui`/`program/feature-dashboard` today, including the largest, `program-dashboard.component.ts` (69-line template) — no named exception needed.

`nx g component`'s default (`@nx/angular:component` in `nx.json`) now sets `inlineTemplate: true`, so this is the default output of the generator, not something to remember to opt into by hand.

## Considered Options

- **Inline everything (template + styles) uniformly**, matching the four pre-existing inline-template components (`auth.component.ts`, `confirmation-dialog.component.ts`, `muscle-multi-select.component.ts`, `discard-changes-dialog.component.ts`). Rejected for styles specifically, for now: no immediate pain point pushed on it, and it's the easier direction to add later than to walk back.
- **Array-wrapped styles**, a single template-literal element inside a `styles` array (the form `muscle-multi-select.component.ts` already uses) instead of a bare string. Rejected — Angular's current form is a bare string, and it's already the majority of existing precedent.

## Consequences

- Prettier (3.6.2, already installed) formats inline templates automatically — no plugin or config needed. Embedded templates wrap at the repo's default 120-char width, not the 140-char width the `.prettierrc` `overrides` block grants `*.html` files (that override can't reach markup embedded inside a `.ts` file). Accepted as-is.
- `plugin:@angular-eslint/template/process-inline-templates` is already enabled in `.eslintrc.json`, so template-linting (accessibility, etc.) already covers inline templates the same as external ones — nothing to change there.
- Applies as a going-forward, repo-wide convention. Retrofitting existing split-file components onto it is scoped separately, feature by feature — see [Retrofit `program` components to single-file](../../.scratch/training-planner-architecture-review/issues/05-retrofit-program-components-to-single-file.md) for the Training Planner feature's retrofit.
